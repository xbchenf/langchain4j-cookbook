## 前言

在第18篇文章中，我们学习了如何创建和调用**单步 Agent**（CvGenerator），它能够根据用户的生活故事生成一份完整的简历。但在实际业务场景中，往往需要**多个步骤**才能完成一个复杂任务：

**场景：智能招聘系统**
```
用户需求：根据候选人信息和职位描述，生成一份定制化的简历

传统方式（手动串联）：
String masterCv = cvGenerator.generateCv(lifeStory);
String tailoredCv = cvTailor.tailorCv(masterCv, jobDescription);
// ❌ 代码耦合，难以维护，无法复用

理想方式（工作流编排）：
工作流自动串联 Agent 1 → Agent 2
✅ 解耦、可维护、可复用
```

**问题 1：如何在 Agent 之间传递数据？**
```
Agent 1 输出：masterCv
Agent 2 输入：masterCv

如何确保数据正确传递？❓
```

**问题 2：如何保留中间结果？**
```
用户可能想查看：
- 原始简历（masterCv）
- 定制后的简历（tailoredCv）
- 甚至用户原始信息（lifeStory）

如何同时返回多个结果？❓
```

**问题 3：有两种编程模式，该选哪种？**
```
模式 1：无类型代理（UntypedAgent）
- 通过 Map 传递参数
- 灵活但缺乏类型安全

模式 2：类型化代理（Typed Agent）
- 通过接口定义方法签名
- 类型安全但需要额外定义接口

如何选择？❓
```

这些问题正是**顺序工作流**要解决的核心挑战。顺序工作流是 Agentic AI 中最基础、最常用的编排模式，它将多个 Agent 按顺序串联成流水线，自动处理数据传递和状态管理。

准备好了吗？让我们开始学习顺序工作流！

## 一、什么是顺序工作流？

### 1.1 核心概念

**顺序工作流（Sequential Workflow）**：将多个 Agent 按固定顺序串联执行，前一个 Agent 的输出作为后一个 Agent 的输入。

```
用户输入 → Agent 1 → Agent 2 → Agent 3 → ... → 最终输出
            ↓           ↓           ↓
         输出1       输出2       输出3
         
所有中间结果存储在 AgenticScope 中
```

**类比**：工厂流水线
- 原材料 → 加工站 1 → 加工站 2 → 加工站 3 → 成品
- 每个加工站只负责一道工序
- 半成品在工序之间传递

### 1.2 与单步 Agent 的对比

| 维度 | 单步 Agent | 顺序工作流 |
|------|-----------|-----------|
| **Agent 数量** | 1 个 | 2+ 个 |
| **执行方式** | 单次调用 | 多次串联 |
| **数据传递** | 无需 | 通过 AgenticScope |
| **中间结果** | 无 | 保留所有中间状态 |
| **适用场景** | 简单任务 | 多阶段任务 |

### 1.3 典型应用场景

**场景 1：简历生成与优化**
```
用户信息 → 简历生成 → 简历定制 → 定制简历
          (Agent 1)   (Agent 2)
```

**场景 2：代码开发流程**
```
需求文档 → 代码生成 → 代码审查 → 单元测试 → 最终代码
          (Agent 1)   (Agent 2)   (Agent 3)
```

**场景 3：内容创作**
```
主题 → 大纲生成 → 内容撰写 → 编辑润色 → 最终文章
       (Agent 1)   (Agent 2)   (Agent 3)
```

**场景 4：数据分析**
```
原始数据 → 数据清洗 → 特征工程 → 模型训练 → 预测结果
          (Agent 1)   (Agent 2)   (Agent 3)
```

## 二、实战案例：简历生成与定制

### 2.1 场景描述

**业务需求**：
1. 根据候选人的生活故事生成一份完整简历
2. 根据目标职位的描述，对简历进行定制化优化
3. 返回原始简历、定制简历、以及用户原始信息

**技术方案**：
- **Agent 1**：CvGenerator（简历生成器）
- **Agent 2**：CvTailor（简历定制器）
- **工作流**：顺序工作流串联两个 Agent

### 2.2 定义第一个 Agent：简历生成器

这个 Agent 在第18篇已经介绍过，这里快速回顾：

```java
package com.langchain4j.agentic._01_basic;

import dev.langchain4j.agentic.Agent;
import dev.langchain4j.service.UserMessage;
import dev.langchain4j.service.V;

public interface CvGenerator {
    
    @UserMessage("""
        以下是我的人生和职业发展轨迹信息，
        请将其整理成一份清晰完整的简历。
        不要虚构事实，也不要遗漏任何技能或经历。
        
        我的个人经历：{{lifeStory}}
        """)
    @Agent("基于用户提供的信息生成清晰的简历")
    String generateCv(@V("lifeStory") String userInfo);
}
```

**关键点**：
- 输入：`lifeStory`（用户生活故事）
- 输出：`masterCv`（完整简历）
- `outputKey` 必须设置为 `"masterCv"`

### 2.3 定义第二个 Agent：简历定制器

```java
package com.langchain4j.agentic._02_sequential_workflow;

import dev.langchain4j.agentic.Agent;
import dev.langchain4j.service.SystemMessage;
import dev.langchain4j.service.UserMessage;
import dev.langchain4j.service.V;

/**
 * 简历定制器接口
 */
public interface CvTailor {

    /**
     * 根据特定指令定制简历
     * 
     * @param masterCv 原始完整简历
     * @param instructions 定制指令（如职位描述）
     * @return 定制后的简历
     */
    @Agent("根据特定指令定制简历")
    @SystemMessage("""
        以下是一份需要根据特定职位描述、反馈或其他指令进行定制的简历。
        你可以优化简历以满足要求，但不要虚构事实。
        如果删除不相关的内容能使简历更好地符合指令，可以删除。
        目标是让申请人获得面试机会，并能够在面试中展现简历中的能力。
        不要让简历过长。
        
        原始完整简历：{{masterCv}}
        """)
    @UserMessage("""
        以下是定制简历的指令：{{instructions}}
        """)
    String tailorCv(@V("masterCv") String masterCv, 
                    @V("instructions") String instructions);
}
```

**关键点**：
- 输入 1：`masterCv`（来自 Agent 1 的输出）
- 输入 2：`instructions`（外部传入的职位描述）
- 输出：`tailoredCv`（定制后的简历）
- **注意**：`@V("masterCv")` 必须与 Agent 1 的 `outputKey` 一致

### 2.4 数据传递机制

```
AgenticScope 状态流转：

初始状态：
{
  "lifeStory": "...",      // 用户输入
  "instructions": "..."    // 用户输入
}

Agent 1 执行后：
{
  "lifeStory": "...",
  "instructions": "...",
  "masterCv": "..."        // Agent 1 输出
}

Agent 2 执行后：
{
  "lifeStory": "...",
  "instructions": "...",
  "masterCv": "...",
  "tailoredCv": "..."      // Agent 2 输出
}
```

**关键规则**：
1. Agent 1 的 `outputKey` = Agent 2 的输入变量名
2. 所有中间结果都保存在 AgenticScope 中
3. 可以随时读取任意中间状态

## 三、无类型工作流实现

### 3.1 什么是无类型工作流？

**无类型工作流（UntypedAgent）**：不使用类型化接口，通过 `Map<String, Object>` 传递参数的工作流。

**特点**：
- ✅ 灵活，无需定义额外接口
- ✅ 快速原型开发
- ❌ 缺乏编译时类型检查
- ❌ 运行时可能出错

### 3.2 完整代码实现

```java
package com.langchain4j;

import com.langchain4j.agentic._01_basic.CvGenerator;
import com.langchain4j.agentic._02_sequential_workflow.CvTailor;
import com.langchain4j.util.StringLoader;
import dev.langchain4j.agentic.AgenticServices;
import dev.langchain4j.agentic.UntypedAgent;
import dev.langchain4j.model.openai.OpenAiChatModel;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;

import java.util.Map;

@SpringBootTest
public class _02_SequentialWorkflowTest {
    
    @Autowired
    private OpenAiChatModel openAiChatModel;

    @Test
    public void testUntypedWorkflow() throws Exception {
        
        // ==================== 第一步：创建子 Agent ====================
        
        CvGenerator cvGenerator = AgenticServices
            .agentBuilder(CvGenerator.class)
            .chatModel(openAiChatModel)
            .outputKey("masterCv")  // 输出键名，传递给下一个 Agent
            .build();
        
        CvTailor cvTailor = AgenticServices
            .agentBuilder(CvTailor.class)
            .chatModel(openAiChatModel)
            .outputKey("tailoredCv")  // 最终输出键名
            .build();

        // ==================== 第二步：加载输入数据 ====================
        
        String lifeStory = StringLoader.loadFromResource("/documents/user_life_story.txt");
        String instructions = "根据以下职位描述调整简历。" + 
            StringLoader.loadFromResource("/documents/job_description_backend.txt");

        // ==================== 第三步：构建顺序工作流 ====================
        
        UntypedAgent tailoredCvGenerator = AgenticServices
            .sequenceBuilder()  // 无类型工作流构建器
            .subAgents(cvGenerator, cvTailor)  // 添加子 Agent（顺序重要）
            .outputKey("tailoredCv")  // 最终输出键名
            .build();

        // ==================== 第四步：准备参数 Map ====================
        
        Map<String, Object> arguments = Map.of(
            "lifeStory", lifeStory,       // 与 CvGenerator 的 @V("lifeStory") 匹配
            "instructions", instructions  // 与 CvTailor 的 @V("instructions") 匹配
        );

        // ==================== 第五步：调用工作流 ====================
        
        String tailoredCv = (String) tailoredCvGenerator.invoke(arguments);

        // ==================== 第六步：输出结果 ====================
        
        System.out.println("=== 定制简历（无类型） ===");
        System.out.println(tailoredCv);
    }
}
```

### 3.3 代码解析

**1. 创建子 Agent**
```java
CvGenerator cvGenerator = AgenticServices
    .agentBuilder(CvGenerator.class)
    .chatModel(openAiChatModel)
    .outputKey("masterCv")  // ⚠️ 关键：与 CvTailor 的输入变量名一致
    .build();
```

**2. 构建工作流**
```java
UntypedAgent tailoredCvGenerator = AgenticServices
    .sequenceBuilder()  // 无类型构建器
    .subAgents(cvGenerator, cvTailor)  // 顺序很重要！
    .outputKey("tailoredCv")  // 指定最终输出
    .build();
```

**3. 准备参数**
```java
Map<String, Object> arguments = Map.of(
    "lifeStory", lifeStory,
    "instructions", instructions
);
```
- Key 必须与 Agent 接口的 `@V()` 注解一致
- Value 可以是任意类型

**4. 调用工作流**
```java
String tailoredCv = (String) tailoredCvGenerator.invoke(arguments);
```
- 返回类型需要强制转换
- 只能获取最终输出，无法直接访问中间状态

## 四、类型化工作流实现

### 4.1 什么是类型化工作流？

**类型化工作流（Typed Agent）**：通过定义类型化接口，提供编译时类型检查的工作流。

**特点**：
- ✅ 类型安全，编译时检查
- ✅ IDE 自动补全
- ✅ 可以访问完整的 AgenticScope
- ❌ 需要额外定义接口

### 4.2 定义工作流接口

```java
package com.langchain4j.agentic._02_sequential_workflow;

import dev.langchain4j.agentic.Agent;
import dev.langchain4j.agentic.scope.ResultWithAgenticScope;
import dev.langchain4j.service.V;

import java.util.Map;

/**
 * 顺序工作流接口
 */
public interface SequenceCvGenerator {
    
    /**
     * 生成简历并定制
     * 
     * @param lifeStory 用户的生活故事
     * @param instructions 定制指令
     * @return 包含结果和状态的包装对象
     */
    @Agent("基于用户信息生成简历并根据指令定制")
    ResultWithAgenticScope<Map<String, String>> generateTailoredCv(
        @V("lifeStory") String lifeStory, 
        @V("instructions") String instructions
    );
}
```

**关键点**：
- 返回类型：`ResultWithAgenticScope<Map<String, String>>`
  - `result()`：自定义输出结果
  - `agenticScope()`：完整的工作流状态
- 输入参数：与子 Agent 的输入变量名一致

### 4.3 完整代码实现

```java
@Test
public void testTypedWorkflow() throws Exception {
    
    // ==================== 第一步：创建子 Agent（与无类型相同）====================
    
    CvGenerator cvGenerator = AgenticServices
        .agentBuilder(CvGenerator.class)
        .chatModel(openAiChatModel)
        .outputKey("masterCv")
        .build();
    
    CvTailor cvTailor = AgenticServices
        .agentBuilder(CvTailor.class)
        .chatModel(openAiChatModel)
        .outputKey("tailoredCv")
        .build();

    // ==================== 第二步：加载输入数据 ====================
    
    String lifeStory = StringLoader.loadFromResource("/documents/user_life_story.txt");
    String instructions = "根据以下职位描述调整简历。" + 
        StringLoader.loadFromResource("/documents/job_description_backend.txt");

    // ==================== 第三步：构建类型化工作流 ====================
    
    SequenceCvGenerator sequenceCvGenerator = AgenticServices
        .sequenceBuilder(SequenceCvGenerator.class)  // 指定类型化接口
        .subAgents(cvGenerator, cvTailor)
        .outputKey("bothCvsAndLifeStory")  // 自定义输出键名
        .output(agenticScope -> {  // 自定义输出处理
            Map<String, String> bothCvsAndLifeStory = Map.of(
                "lifeStory", agenticScope.readState("lifeStory", ""),
                "masterCv", agenticScope.readState("masterCv", ""),
                "tailoredCv", agenticScope.readState("tailoredCv", "")
            );
            return bothCvsAndLifeStory;
        })
        .build();

    // ==================== 第四步：调用工作流 ====================
    
    ResultWithAgenticScope<Map<String, String>> result = 
        sequenceCvGenerator.generateTailoredCv(lifeStory, instructions);

    // ==================== 第五步：提取结果和状态 ====================
    
    Map<String, String> data = result.result();
    AgenticScope scope = result.agenticScope();
    
    System.out.println("=== 用户信息（输入） ===");
    System.out.println(data.get("lifeStory").substring(0, 100) + "...");
    
    System.out.println("\n=== 主简历（中间变量） ===");
    System.out.println(data.get("masterCv").substring(0, 100) + "...");
    
    System.out.println("\n=== 定制简历（输出） ===");
    System.out.println(data.get("tailoredCv"));
    
    System.out.println("\n=== 工作流状态 ===");
    System.out.println(AgenticScopePrinter.printPretty(scope, 100));
}
```

### 4.4 代码解析

**1. 自定义输出处理**
```java
.output(agenticScope -> {
    Map<String, String> bothCvsAndLifeStory = Map.of(
        "lifeStory", agenticScope.readState("lifeStory", ""),
        "masterCv", agenticScope.readState("masterCv", ""),
        "tailoredCv", agenticScope.readState("tailoredCv", "")
    );
    return bothCvsAndLifeStory;
})
```
- 从 AgenticScope 中读取任意状态
- 组合成自定义输出格式
- 可以同时返回多个结果

**2. 调用工作流**
```java
ResultWithAgenticScope<Map<String, String>> result = 
    sequenceCvGenerator.generateTailoredCv(lifeStory, instructions);
```
- 像调用普通方法一样
- 返回包装对象，包含结果和状态

**3. 提取结果**
```java
Map<String, String> data = result.result();
AgenticScope scope = result.agenticScope();
```
- `result()`：自定义输出
- `agenticScope()`：完整状态（包括所有中间变量）

## 五、两种模式对比

### 5.1 功能对比

| 维度 | 无类型工作流 | 类型化工作流 |
|------|-------------|-------------|
| **定义方式** | 无需接口 | 需要定义接口 |
| **参数传递** | `Map<String, Object>` | 方法参数 |
| **返回类型** | `Object`（需强制转换） | `ResultWithAgenticScope<T>` |
| **类型安全** | ❌ 运行时检查 | ✅ 编译时检查 |
| **IDE 支持** | ❌ 无自动补全 | ✅ 自动补全 |
| **访问状态** | ❌ 只能获取最终输出 | ✅ 可访问完整 AgenticScope |
| **灵活性** | ✅ 高 | ⚠️ 中 |
| **适用场景** | 快速原型 | 生产环境 |

### 5.2 代码复杂度对比

**无类型工作流**：
```java
// 优点：代码简洁
UntypedAgent agent = AgenticServices
    .sequenceBuilder()
    .subAgents(agent1, agent2)
    .outputKey("result")
    .build();

Map<String, Object> args = Map.of("input", value);
String result = (String) agent.invoke(args);
```

**类型化工作流**：
```java
// 缺点：需要额外定义接口
interface MyWorkflow {
    ResultWithAgenticScope<String> execute(@V("input") String input);
}

MyWorkflow agent = AgenticServices
    .sequenceBuilder(MyWorkflow.class)
    .subAgents(agent1, agent2)
    .output(agenticScope -> agenticScope.readState("result", ""))
    .build();

ResultWithAgenticScope<String> result = agent.execute(value);
```

### 5.3 选择建议

**使用无类型工作流**：
- ✅ 快速原型开发
- ✅ 简单脚本
- ✅ 一次性任务

**使用类型化工作流**：
- ✅ 生产环境
- ✅ 团队协作
- ✅ 需要访问中间状态
- ✅ 长期维护的项目

## 六、常见问题与避坑指南

### ❌ 问题 1：Agent 之间数据传递失败

**现象**：第二个 Agent 收不到第一个 Agent 的输出，报错 `null`

**原因**：`outputKey` 与输入变量名不匹配

**解决方案**：
```java
// Agent 1
.outputKey("masterCv")  // 输出键名

// Agent 2
String tailorCv(@V("masterCv") String masterCv, ...)  // 输入变量名必须一致
```

**调试技巧**：
```java
// 打印 AgenticScope 状态
System.out.println(AgenticScopePrinter.printPretty(scope, 100));
// 检查 masterCv 是否存在
```

### ❌ 问题 2：顺序错误导致结果异常

**现象**：输出结果不符合预期

**原因**：`.subAgents()` 中的 Agent 顺序错误

**解决方案**：
```java
// ✅ 正确顺序
.subAgents(cvGenerator, cvTailor)

// ❌ 错误顺序（cvTailor 需要 masterCv，但此时还未生成）
.subAgents(cvTailor, cvGenerator)
```

**最佳实践**：
- 按照数据依赖关系排序
- 在注释中说明每个 Agent 的职责

### ❌ 问题 3：无法访问中间结果

**现象**：只能获取最终输出，想看中间结果怎么办？

**解决方案**：
```java
// 方案 1：使用类型化工作流
.output(agenticScope -> {
    return Map.of(
        "masterCv", agenticScope.readState("masterCv", ""),
        "tailoredCv", agenticScope.readState("tailoredCv", "")
    );
})

// 方案 2：调试时打印 AgenticScope
System.out.println(AgenticScopePrinter.printPretty(scope, 100));
```

### ❌ 问题 4：参数 Map 的 Key 不匹配

**现象**：运行时抛出异常 `Missing required parameter: xxx`

**原因**：Map 的 Key 与 Agent 接口的 `@V()` 注解不一致

**解决方案**：
```java
// Agent 接口
String generateCv(@V("lifeStory") String userInfo);

// 调用时
Map<String, Object> args = Map.of(
    "lifeStory", lifeStory  // ✅ Key 必须是 "lifeStory"
);
```

## 七、性能分析与优化

### 7.1 性能特点

**串行执行**：
```
Agent 1（2 秒）→ Agent 2（2 秒）→ Agent 3（2 秒）
总耗时：6 秒
```

**优点**：
- ✅ 逻辑清晰，易于理解
- ✅ 数据依赖明确

**缺点**：
- ❌ 耗时累加
- ❌ 无法并行优化

### 7.2 优化策略

**策略 1：减少 Agent 数量**
```
合并职责相近的 Agent
Agent 1 + Agent 2 → Agent 1_2
```

**策略 2：优化 Prompt**
```
精简 Prompt，减少 Token 数量
降低 LLM 响应时间
```

**策略 3：缓存中间结果**
```java
// 如果 masterCv 不变，可以缓存
if (cache.contains(lifeStory)) {
    return cache.get(lifeStory);
}
```

**策略 4：异步执行（不适用顺序工作流）**
- 顺序工作流本质是串行的
- 如需并行，考虑并行工作流（第21篇）

## 结语

通过本文，我们深入学习了顺序工作流的设计与实现：

1. ✅ **顺序工作流原理**：多阶段流水线，数据传递机制
2. ✅ **无类型工作流**：快速原型，灵活但缺乏类型安全
3. ✅ **类型化工作流**：生产环境，类型安全且可访问完整状态
4. ✅ **两种模式对比**：根据场景选择合适的实现方式
5. ✅ **常见问题**：数据传递、顺序错误、中间结果访问

**关键收获**：
- 顺序工作流是 Agentic AI 中最基础的编排模式
- `outputKey` 必须与下一个 Agent 的输入变量名一致
- 类型化工作流适合生产环境，无类型工作流适合快速原型
- AgenticScope 保留所有中间状态，便于调试和审计
