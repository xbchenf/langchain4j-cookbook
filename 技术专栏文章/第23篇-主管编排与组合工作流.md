## 前言

在前面的文章中，我们学习了5种基础工作流模式：
- ✅ 第19篇：**顺序工作流** - 固定顺序执行
- ✅ 第20篇：**循环工作流** - 迭代直到达标
- ✅ 第21篇：**并行工作流** - 并发执行加速
- ✅ 第22篇：**条件分支** - 基于条件路由

这些基础工作流都是**确定性**的：执行顺序和逻辑在编码时就已确定。但在实际业务场景中，往往需要**更灵活的编排方式**：

**场景 1：动态调度**
```
用户需求："请评审这份简历并做出决策"

传统方式（硬编码）：
if (评分 >= 0.8) {
    安排面试();
} else {
    发送拒绝邮件();
}

问题：
- 规则变化需要重新部署 ❌
- 无法处理复杂语义 ❌
- 缺乏灵活性 ❌

理想方式（AI 自主决策）：
Supervisor Agent 根据上下文自主决定：
1. 先调用 HR 评审员
2. 再调用经理评审员
3. 根据评审结果决定是否安排面试
```

**场景 2：复杂流程组合**
```
完整招聘流程：
1. 简历生成（单步 Agent）
2. 质量检查（循环工作流）
3. 多方评审（并行工作流）
4. 决策执行（条件分支）

挑战：
- 如何将4种工作流组合在一起？❓
- 如何在不同工作流之间传递数据？❓
- 如何管理复杂的状态？❓
```

**这就是主管编排和组合工作流的价值所在！**

## 一、主管编排：智能调度的项目经理

### 1.1 什么是 Supervisor Agent？

**Supervisor Agent**（主管代理）是一个**主 Agent**，它负责调度和协调多个**子 Agent**，类似于项目经理的角色。

```
┌──────────────────┐
│  Supervisor Agent │ ← 项目经理
└────────┬─────────┘
         │
    ┌────┼────┬────────┬────────┐
    ▼    ▼    ▼        ▼        ▼
┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐
│AgentA││AgentB││AgentC││AgentD││AgentE│
└──────┘└──────┘└──────┘└──────┘└──────┘
     子 Agent 团队
```

**核心特点**：
- 🎯 **自主决策**：LLM 根据上下文自主决定调用哪个子 Agent
- 🔄 **动态规划**：运行时生成执行计划，而非硬编码
- 📊 **结果汇总**：收集所有子 Agent 的结果并生成摘要

---

### 1.2 与条件分支的对比

| 特性 | 条件分支 | Supervisor |
|------|---------|-----------|
| **路由方式** | 硬编码规则（if-else） | LLM 自主决策 |
| **灵活性** | 低（规则固定） | 高（语义理解） |
| **执行速度** | 快（无额外调用） | 慢（需 LLM 判断） |
| **Token 消耗** | 无 | 有（Supervisor 调用） |
| **适用场景** | 规则明确且稳定 | 规则复杂或多变 |
| **维护成本** | 低 | 中（需优化提示词） |

**示例对比**：

```java
// ❌ 条件分支：硬编码路由
.subAgents(scope -> review.score >= 0.8, interviewOrganizer)
.subAgents(scope -> review.score < 0.8, emailAssistant)

// ✅ Supervisor：自主决策
SupervisorAgent supervisor = AgenticServices.supervisorBuilder()
    .chatModel(openAiChatModel)
    .subAgents(hrReviewer, managerReviewer, teamReviewer, 
               interviewOrganizer, emailAssistant)
    .build();

// Supervisor 会根据上下文自主决定调用顺序
String result = supervisor.invoke("请评审这份简历并做出决策");
```

### 1.3 实战案例：HiringSupervisor

#### 业务场景

我们要构建一个**智能招聘主管系统**：

```
输入：
- 候选人简历
- 候选人联系方式
- 职位描述
- HR 要求
- 电话面试笔记

处理流程（由 Supervisor 自主决定）：
1. 调用 HR 评审员 → 检查薪资、可用性、工作权限
2. 调用经理评审员 → 检查技术匹配度
3. 调用团队成员评审员 → 检查团队契合度
4. 根据评审结果：
   - 如果评分高 → 调用 InterviewOrganizer 安排面试
   - 如果评分低 → 调用 EmailAssistant 发送拒绝邮件

输出：
- 综合评审报告
- 最终决策（安排面试 or 拒绝）
```

**关键步骤拆解**：

##### ① 定义子代理

```java

    .chatModel(openAiChatModel)

ManagerCvReviewer managerReviewer = AgenticServices.agentBuilder(ManagerCvReviewer.class)

```

**注意**：
- 如果多个代理使用相同的方法名（如 `reviewCv`），最好给代理命名：
  ```java
  @Agent(name = "managerReviewer", description = "根据职位描述评审简历，提供反馈和评分")
  ```

##### ② 构建主管代理

```java
SupervisorAgent hiringSupervisor = AgenticServices.supervisorBuilder()
    .chatModel(openAiChatModel)
    .subAgents(hrReviewer, managerReviewer, teamReviewer, 
              interviewOrganizer, emailAssistant)
    .contextGenerationStrategy(SupervisorContextStrategy.CHAT_MEMORY_AND_SUMMARIZATION)
    .responseStrategy(SupervisorResponseStrategy.SUMMARY)
    .supervisorContext("始终使用可用的完整评审团。始终用英语回答。")
    .build();
```

**参数说明**：

**`contextGenerationStrategy`**：上下文生成策略
- `CHAT_MEMORY`：使用对话记忆
- `SUMMARIZATION`：使用摘要
- `CHAT_MEMORY_AND_SUMMARIZATION`：两者结合（推荐）

**`responseStrategy`**：响应策略
- `LAST`：返回最后一个子 Agent 的响应
- `SUMMARY`：生成执行过程的摘要（推荐）
- `SCORED`：使用评分模型决定返回 LAST 还是 SUMMARY

**`supervisorContext`**：主管行为上下文（可选）
- 指导 Supervisor 的行为策略
- 例如："先检查 HR，必要时升级，拒绝低匹配度候选人"

##### ③ 调用主管

```java
String result = (String) hiringSupervisor.invoke(
    "评估以下候选人：\n" +
    "候选人简历：\n" + candidateCv + "\n\n" +
    "候选人联系方式：\n" + candidateContact + "\n\n" +

    "HR 要求：\n" + hrRequirements + "\n\n" +

```

**重要**：
- 使用**自然语言**描述任务，而非硬编码参数
- Supervisor 会自主解析需求并制定执行计划

### 1.4 工作流程详解

```
用户请求："评估以下候选人..."
    │
    ▼
┌──────────────────────┐
│  Supervisor Agent    │
│  分析用户意图         │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  生成执行计划         │
│  1. 调用 HR 评审员    │
│  2. 调用经理评审员    │
│  3. 调用团队成员评审员│
│  4. 根据结果决策      │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  执行子 Agent 1       │
│  HR 评审员            │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  审查计划             │
│  下一步调用谁？        │
└──────────┬───────────┘
           │
           ▼
┌──────────────────────┐
│  执行子 Agent 2       │
│  经理评审员            │
└──────────┬───────────┘
           │
           ▼
      ...（继续执行）
           │
           ▼
┌──────────────────────┐
│  生成摘要             │
│  返回给用户            │
└──────────────────────┘
```

**重要说明**：
- ⚠️ Supervisor **一次只调用一个子 Agent**，然后审查计划选择下一个
- ⚠️ Supervisor **无法并行执行**子 Agent
- ⚠️ 如果子 Agent 标记为异步，Supervisor 会覆盖该设置并发出警告

### 1.6 优缺点分析

#### 优点

✅ **灵活性高**：无需硬编码规则，适应性强  
✅ **可扩展性好**：新增子 Agent 无需修改现有代码  
✅ **语义理解**：能理解复杂的自然语言指令  
✅ **自主决策**：根据上下文动态调整执行计划  

#### 缺点

❌ **执行速度慢**：需要多次 LLM 调用（Supervisor + 子 Agent）  
❌ **Token 消耗高**：Supervisor 的决策过程消耗额外 Token  
❌ **可能路由错误**：LLM 可能做出错误的调度决策  
❌ **调试困难**：执行路径不固定，难以追踪问题

## 二、组合工作流：多种模式的嵌套使用

### 2.1 什么是组合工作流？

**组合工作流**（Composed Workflow）是将**多种基础工作流模式**嵌套组合，形成复杂的业务流程。

```
组合工作流 = 顺序 + 并行 + 循环 + 条件分支
```

**核心价值**：
- 🔗 **复用性**：将已有的工作流作为子模块复用
- 🏗️ **层次化**：外层工作流调用内层工作流
- 📦 **模块化**：每个工作流独立开发、测试

---

### 2.2 常见组合方式

#### 组合 1：顺序 + 并行

```
外层：顺序工作流
├─ 步骤1：初始化（单步 Agent）
├─ 步骤2：多方评审（并行工作流）
│   ├─ HR 评审
│   ├─ 经理评审
│   └─ 团队成员评审
└─ 步骤3：汇总结果（单步 Agent）
```

**适用场景**：需要先串行准备数据，再并行处理，最后串行汇总

---

#### 组合 2：循环 + 条件分支

```
外层：循环工作流
├─ 步骤1：优化内容（单步 Agent）
├─ 步骤2：质量检查（单步 Agent）
└─ 退出条件判断
    ├─ 评分 >= 0.8 → 退出循环
    └─ 评分 < 0.8 → 继续循环
```

**适用场景**：持续优化直到满足某个条件

---

#### 组合 3：并行 + 循环

```
外层：并行工作流
├─ 分支1：优化器 A（循环工作流）
│   └─ 迭代直到达标
├─ 分支2：优化器 B（循环工作流）
│   └─ 迭代直到达标
└─ 聚合器：合并结果
```

**适用场景**：多个优化任务同时进行，每个都需要迭代

### 2.3 实战案例：完整招聘系统

#### 业务场景

我们要构建一个**端到端的智能招聘系统**，包含两个主要部分：

**部分 1：候选人工作流**
```
目标：从生活故事生成优化后的简历

流程：
1. 简历生成（CvGenerator）
2. 初次评审（CvReviewer）
3. 循环优化（ScoredCvTailor + CvReviewer）
   └─ 直到评分 >= 0.8 或达到最大迭代次数

输出：优化后的简历
```

**部分 2：招聘团队工作流**
```
目标：评审简历并做出决策

流程：
1. 并行评审（HrCvReviewer + ManagerCvReviewer + TeamMemberCvReviewer）
2. 聚合结果（计算平均分）
3. 条件决策
   ├─ 评分 >= 0.8 → 安排面试（InterviewOrganizer）
   └─ 评分 < 0.8 → 发送拒绝邮件（EmailAssistant）

输出：面试安排 or 拒绝邮件
```

#### 完整代码

```java
package com.langchain4j;

import com.langchain4j.agentic._01_basic.CvGenerator;
import com.langchain4j.agentic._03_loop_workflow.CvReviewer;
import com.langchain4j.agentic._03_loop_workflow.ScoredCvTailor;
import com.langchain4j.agentic._04_parallel_workflow.HrCvReviewer;
import com.langchain4j.agentic._04_parallel_workflow.ManagerCvReviewer;
import com.langchain4j.agentic._04_parallel_workflow.TeamMemberCvReviewer;
import com.langchain4j.agentic._05_conditional_workflow.*;
import com.langchain4j.agentic._06_composed_workflow.CandidateWorkflow;
import com.langchain4j.agentic._06_composed_workflow.HiringTeamWorkflow;
import com.langchain4j.domain.CvReview;
import com.langchain4j.util.StringLoader;
import dev.langchain4j.agentic.AgenticServices;
import dev.langchain4j.agentic.UntypedAgent;
import dev.langchain4j.model.openai.OpenAiChatModel;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.context.SpringBootTest;

import java.util.Map;
import java.util.concurrent.Executors;

@SpringBootTest
public class _06_ComposedWorkflowTest {

    @Autowired
    private OpenAiChatModel openAiChatModel;

    @Test
    public void testComposedWorkflow() throws Exception {
        
        ////////////////// 候选人组合工作流 //////////////////////
        
        // 1. 创建所有必要的代理
        CvGenerator cvGenerator = AgenticServices
                .agentBuilder(CvGenerator.class)
                .chatModel(openAiChatModel)
                .outputKey("cv")
                .build();

        ScoredCvTailor scoredCvTailor = AgenticServices
                .agentBuilder(ScoredCvTailor.class)
                .chatModel(openAiChatModel)
                .outputKey("cv")
                .build();

        CvReviewer cvReviewer = AgenticServices
                .agentBuilder(CvReviewer.class)
                .chatModel(openAiChatModel)
                .outputKey("cvReview")
                .build();

        // 2. 创建简历改进的循环工作流
        UntypedAgent cvImprovementLoop = AgenticServices
                .loopBuilder()
                .subAgents(scoredCvTailor, cvReviewer)
                .outputKey("cv")
                .exitCondition(agenticScope -> {
                    CvReview review = (CvReview) agenticScope.readState("cvReview");
                    System.out.println("简历评审评分：" + review.score);
                    if (review.score >= 0.8)
                        System.out.println("简历足够好，退出循环。\n");
                    return review.score >= 0.8;
                })
                .maxIterations(3)
                .build();

        // 3. 创建完整的候选人工作流：生成 → 评审 → 改进循环
        CandidateWorkflow candidateWorkflow = AgenticServices
                .sequenceBuilder(CandidateWorkflow.class)
                .subAgents(cvGenerator, cvReviewer, cvImprovementLoop)
                // ⭐ 这里我们在 sequenceBuilder 中使用组合代理 cvImprovementLoop
                // 我们还需要 cvReviewer 以便在进入循环之前生成第一次评审
                .outputKey("cv")
                .build();

        // 4. 加载输入数据
        String lifeStory = StringLoader.loadFromResource("/documents/user_life_story.txt");
        String jobDescription = StringLoader.loadFromResource("/documents/job_description_backend.txt");

        // 5. 执行候选人工作流
        String candidateResult = candidateWorkflow.processCandidate(lifeStory, jobDescription);

        System.out.println("=== 候选人工作流完成 ===");
        System.out.println("最终简历：" + candidateResult);

        System.out.println("\n\n\n\n");

        ////////////////// 招聘团队组合工作流 //////////////////////
        
        // 1. 创建所有必要的代理
        HrCvReviewer hrCvReviewer = AgenticServices
                .agentBuilder(HrCvReviewer.class)
                .chatModel(openAiChatModel)
                .outputKey("hrReview")
                .build();

        ManagerCvReviewer managerCvReviewer = AgenticServices
                .agentBuilder(ManagerCvReviewer.class)
                .chatModel(openAiChatModel)
                .outputKey("managerReview")
                .build();

        TeamMemberCvReviewer teamMemberCvReviewer = AgenticServices
                .agentBuilder(TeamMemberCvReviewer.class)
                .chatModel(openAiChatModel)
                .outputKey("teamMemberReview")
                .build();

        EmailAssistant emailAssistant = AgenticServices
                .agentBuilder(EmailAssistant.class)
                .chatModel(openAiChatModel)
                .tools(new OrganizingTools())
                .build();

        InterviewOrganizer interviewOrganizer = AgenticServices
                .agentBuilder(InterviewOrganizer.class)
                .chatModel(openAiChatModel)
                .tools(new OrganizingTools())
                .build();

        // 2. 创建并行评审工作流
        UntypedAgent parallelReviewWorkflow = AgenticServices
                .parallelBuilder()
                .subAgents(hrCvReviewer, managerCvReviewer, teamMemberCvReviewer)
                .executor(Executors.newFixedThreadPool(3))
                .outputKey("combinedCvReview")
                .output(agenticScope -> {
                    CvReview hrReview = (CvReview) agenticScope.readState("hrReview");
                    CvReview managerReview = (CvReview) agenticScope.readState("managerReview");
                    CvReview teamMemberReview = (CvReview) agenticScope.readState("teamMemberReview");
                    
                    String feedback = String.join("\n",
                            "HR 评审：" + hrReview.feedback,
                            "经理评审：" + managerReview.feedback,
                            "团队成员评审：" + teamMemberReview.feedback
                    );
                    double avgScore = (hrReview.score + managerReview.score + teamMemberReview.score) / 3.0;
                    System.out.println("最终平均简历评审评分：" + avgScore + "\n");
                    
                    return new CvReview(avgScore, feedback);
                })
                .build();

        // 3. 创建最终决策的条件工作流
        UntypedAgent decisionWorkflow = AgenticServices
                .conditionalBuilder()
                .subAgents(agenticScope -> 
                    ((CvReview) agenticScope.readState("combinedCvReview")).score >= 0.8, 
                    interviewOrganizer)
                .subAgents(agenticScope -> 
                    ((CvReview) agenticScope.readState("combinedCvReview")).score < 0.8, 
                    emailAssistant)
                .build();

        // 4. 创建完整的招聘团队工作流：并行评审 → 决策
        HiringTeamWorkflow hiringTeamWorkflow = AgenticServices
                .sequenceBuilder(HiringTeamWorkflow.class)
                .subAgents(parallelReviewWorkflow, decisionWorkflow)
                .build();

        // 5. 加载输入数据
        String candidateCv = StringLoader.loadFromResource("/documents/tailored_cv.txt");
        String candidateContact = StringLoader.loadFromResource("/documents/candidate_contact.txt");
        String hrRequirements = StringLoader.loadFromResource("/documents/hr_requirements.txt");
        String phoneInterviewNotes = StringLoader.loadFromResource("/documents/phone_interview_notes.txt");

        Map<String, Object> inputData = Map.of(
                "candidateCv", candidateCv,
                "candidateContact", candidateContact,
                "hrRequirements", hrRequirements,
                "phoneInterviewNotes", phoneInterviewNotes,
                "jobDescription", jobDescription
        );

        // 6. 执行招聘团队工作流
        hiringTeamWorkflow.processApplication(
            candidateCv, jobDescription, hrRequirements, 
            phoneInterviewNotes, candidateContact
        );

        System.out.println("=== 招聘团队工作流完成 ===");
        System.out.println("并行评审完成并做出决策");
    }
}
```

#### 代码解析

**关键步骤拆解**：

##### ① 创建循环工作流（内层）

```java
UntypedAgent cvImprovementLoop = AgenticServices
    .loopBuilder()
    .subAgents(scoredCvTailor, cvReviewer)
    .outputKey("cv")
    .exitCondition(agenticScope -> {
        CvReview review = (CvReview) agenticScope.readState("cvReview");
        return review.score >= 0.8;
    })
    .maxIterations(3)
    .build();
```

**作用**：
- 这是一个**独立的循环工作流**
- 可以像普通 Agent 一样被其他工作流调用

##### ② 创建顺序工作流（外层），嵌套循环工作流

```java
CandidateWorkflow candidateWorkflow = AgenticServices
    .sequenceBuilder(CandidateWorkflow.class)
    .subAgents(cvGenerator, cvReviewer, cvImprovementLoop)  // ⭐ 嵌套循环工作流
    .outputKey("cv")
    .build();
```

**关键点**：
- `cvImprovementLoop` 是一个**组合代理**（composed agent）
- 顺序工作流将其视为一个普通的子 Agent
- **所有输入、中间和输出参数都存储在共享的 AgenticScope 中**

##### ③ 创建并行工作流（内层）

```java
UntypedAgent parallelReviewWorkflow = AgenticServices
    .parallelBuilder()
    .subAgents(hrCvReviewer, managerCvReviewer, teamMemberCvReviewer)
    .executor(Executors.newFixedThreadPool(3))
    .outputKey("combinedCvReview")
    .output(agenticScope -> {
        // 聚合三个评审结果
        CvReview hrReview = (CvReview) agenticScope.readState("hrReview");
        CvReview managerReview = (CvReview) agenticScope.readState("managerReview");
        CvReview teamMemberReview = (CvReview) agenticScope.readState("teamMemberReview");
        
        String feedback = String.join("\n", ...);
        double avgScore = (...);
        
        return new CvReview(avgScore, feedback);
    })
    .build();
```

**作用**：
- 并行执行三个评审员
- 聚合器计算平均分并合并反馈

##### ④ 创建条件工作流（内层）

```java
UntypedAgent decisionWorkflow = AgenticServices
    .conditionalBuilder()
    .subAgents(agenticScope -> 
        ((CvReview) agenticScope.readState("combinedCvReview")).score >= 0.8, 
        interviewOrganizer)
    .subAgents(agenticScope -> 
        ((CvReview) agenticScope.readState("combinedCvReview")).score < 0.8, 
        emailAssistant)
    .build();
```

**作用**：
- 根据并行评审的平均分决定下一步操作

##### ⑤ 创建顺序工作流（外层），嵌套并行和条件工作流

```java
HiringTeamWorkflow hiringTeamWorkflow = AgenticServices
    .sequenceBuilder(HiringTeamWorkflow.class)
    .subAgents(parallelReviewWorkflow, decisionWorkflow)  // ⭐ 嵌套两个工作流
    .build();
```

**关键点**：
- 顺序执行：先并行评审，再条件决策
- 两个内层工作流共享同一个 AgenticScope

### 2.5 状态管理与数据传递

#### AgenticScope 共享机制

**核心原理**：
- ✅ 所有工作流（无论嵌套多少层）**共享同一个 AgenticScope**
- ✅ 任何 Agent 写入的数据，其他 Agent 都可以读取
- ✅ 需要注意参数命名唯一性，避免意外覆盖

**示例**：

```java
// 候选人工作流
CandidateWorkflow candidateWorkflow = AgenticServices
    .sequenceBuilder(CandidateWorkflow.class)

// 招聘团队工作流
HiringTeamWorkflow hiringTeamWorkflow = AgenticServices
    .sequenceBuilder(HiringTeamWorkflow.class)
    .subAgents(parallelReviewWorkflow, decisionWorkflow)
    .build();

// 两个工作流共享同一个 AgenticScope
// 如果都写入 "cv"，后执行的会覆盖先执行的
```

```java
// ✅ 使用唯一的参数名
```

### 2.6 性能分析与优化

#### 性能瓶颈

| 瓶颈 | 原因 | 解决方案 |
|------|------|---------|

### 4.2 组合工作流的层数控制

**建议**：
- 📌 **最多 3 层**：外层 → 中层 → 内层
- 📌 **避免过深**：超过 3 层会导致性能下降和调试困难
- 📌 **优先扁平化**：能用一层解决就不用多层

**示例**：

```java
// ✅ 好的设计：2层
sequenceBuilder()
    .subAgents(
        agent1,
        parallelBuilder().subAgents(agent2, agent3).build(),  // 内层
        agent4
    )
    .build();

// ❌ 不好的设计：4层
sequenceBuilder()
    .subAgents(
        loopBuilder()  // 第1层
            .subAgents(
                parallelBuilder()  // 第2层
                    .subAgents(
                        conditionalBuilder()  // 第3层
                            .subAgents(...)
                            .build()
                    )
                    .build()
            )
            .build()
    )
    .build();
```

## 五、常见问题与避坑指南

### 5.1 问题 1：Supervisor 路由错误

**症状**：
```
Supervisor 调用了错误的子 Agent
或者调用顺序不合理
```

**原因**：
- 提示词不够清晰
- 子 Agent 描述不明确
- 上下文信息不足

**解决方案**：

```java
// ✅ 优化 1：明确子 Agent 的描述
@Agent(name = "hrReviewer", 
       description = "从 HR 角度评审简历，检查薪资、可用性、工作权限等")
CvReview reviewCv(...);

// ✅ 优化 2：添加 supervisorContext
.supervisorContext("政策：始终先检查 HR，必要时升级，拒绝低匹配度候选人。")

// ✅ 优化 3：使用 CHAT_MEMORY_AND_SUMMARIZATION
.contextGenerationStrategy(SupervisorContextStrategy.CHAT_MEMORY_AND_SUMMARIZATION)
```

---

### 5.2 问题 2：组合工作流状态冲突

**症状**：
```
后面的 Agent 读取到错误的数据
或者数据被意外覆盖
```

**原因**：
- 多个 Agent 使用相同的 outputKey
- 嵌套工作流之间的参数名冲突

**解决方案**：

```java
// ✅ 使用唯一的参数名
.outputKey("candidate_cv")
.outputKey("optimized_cv")
.outputKey("hr_review")
.outputKey("manager_review")

// ✅ 在文档中记录所有参数名及其用途
```

---

### 5.3 问题 3：嵌套过深导致性能下降

**症状**：
```
工作流执行耗时超过 2 分钟
或者 Token 消耗过高
```

**原因**：
- 嵌套层数过多（超过 3 层）
- 每层都需要额外的 LLM 调用

**解决方案**：

```java
// ✅ 方案 1：减少嵌套层数
// 从 4 层减少到 2 层

// ✅ 方案 2：使用更快的模型
// 如 CEREBRAS（10秒 vs 60秒）

// ✅ 方案 3：增加并行度
.parallelBuilder()
    .subAgents(agent1, agent2, agent3)
    .executor(Executors.newFixedThreadPool(3))
    .build();
```

---

### 5.4 问题 4：异常传播问题

**症状**：
```
某个子 Agent 抛出异常
整个工作流终止
```

**解决方案**：

```java
// ✅ 在子 Agent 中添加异常处理
@Agent("评审简历")
CvReview reviewCv(@V("cv") String cv) {
    try {
        // 执行评审逻辑
        return result;
    } catch (Exception e) {
        System.err.println("评审失败：" + e.getMessage());
        return new CvReview(0.0, "评审执行失败");  // 返回默认值
    }
}

// ✅ 在工作流级别添加异常处理
try {
    workflow.execute();
} catch (Exception e) {
    System.err.println("工作流执行失败：" + e.getMessage());
    // 降级处理
}
```

## 结语

本文深入讲解了两种高级 Agent 编排模式——主管编排（Supervisor Orchestration）与组合工作流（Composed Workflow）。Supervisor Agent 如同项目经理，由 LLM 根据上下文自主决定调用哪个子 Agent、以何种顺序执行，与硬编码条件分支形成鲜明对比；组合工作流则让你将顺序、并行、循环、条件分支自由嵌套，构建出复杂而灵活的智能系统。二者的核心挑战都在于**状态管理**——所有嵌套工作流共享同一个 AgenticScope，参数命名唯一性是避免数据冲突的关键。至此，Agentic 工作流编排的全部模式已讲解完毕，下一篇我们将迈入**人机协同与非 AI Agent**的世界，看如何在工作流中引入人工审批节点和纯代码逻辑，构建真正生产级的混合执行系统。敬请期待！
