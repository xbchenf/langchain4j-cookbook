## 二、Apache Tika 多格式文档解析

### 2.1 为什么需要 Apache Tika？

**问题**：企业文档格式多样，每种格式需要不同的解析器。

```java
// 不使用 Tika：需要手动选择解析器
if (file.endsWith(".pdf")) {
    parser = new PdfBoxDocumentParser();
} else if (file.endsWith(".docx")) {
    parser = new PoiDocumentParser();
} else if (file.endsWith(".txt")) {
    parser = new TextDocumentParser();
}
// ... 更多格式判断 ❌ 代码臃肿
```

**解决方案**：Apache Tika 统一解析多种格式。

```java
// 使用 Tika：自动识别格式
DocumentParser parser = new ApacheTikaDocumentParser();
Document document = parser.parse(inputStream); // ✅ 一行搞定
```

## 三、自定义文档分割策略

### 3.1 为什么需要自定义分割器？

**问题场景**：FAQ 文档的 Q&A 对需要保持完整。

```
FAQ 文档内容：
Q: 如何申请退款？
A: 您可以在订单页面点击"申请退款"按钮...

Q: 配送费是多少？
A: 基础配送费 5 元，满 30 元免配送费...


如果使用固定长度分割（300 字符）：
片段 1: "Q: 如何申请退款？\nA: 您可以在订单页面点击"申请退款"按"
片段 2: "钮...\n\nQ: 配送费是多少？\nA: 基础配送费 5 元，满 30"
片段 3: "元免配送费..."

❌ 问题和答案被拆分到不同片段
❌ 检索时可能只召回问题，没有答案
```

**解决方案**：自定义分割器，按空行分割，保持 Q&A 完整性。

### 3.2 实现自定义分割器

```java
package com.langchain4j;

import dev.langchain4j.data.document.Document;
import dev.langchain4j.data.document.DocumentSplitter;
import dev.langchain4j.data.segment.TextSegment;

import java.util.ArrayList;
import java.util.List;

public class MyDocumentSplitter implements DocumentSplitter {

    /**
     * 使用两个或以上空行分割文档
     * 
     * 正则表达式解释：
     * \\s*\\R\\s*\\R\\s*\\R\\s*
     * - \\s* : 零个或多个空白字符
     * - \\R  : 任意换行符（Unix \n, Windows \r\n, Mac \r）
     * - 重复三次表示至少两个空行
     */
    public static final String SPLIT_REGEX = "\\s*\\R\\s*\\R\\s*\\R\\s*";

    @Override
    public List<TextSegment> split(Document document) {
        List<TextSegment> segments = new ArrayList<>();
        
        // 按正则表达式分割文档
        String[] parts = document.text().split(SPLIT_REGEX);
        
        for (String part : parts) {
            if (!part.trim().isEmpty()) {
                // 创建文本片段
                segments.add(TextSegment.from(part));
            }
        }
        
        return segments;
    }
}
```

### 3.3 使用自定义分割器

```java

// 分割文档

```

```
--- 片段 2 ---

```

✅ **Q&A 对保持完整！**

### 3.4 LangChain4j 内置分割器对比

LangChain4j 提供了 7 种内置分割器：

| 分割器 | 适用场景 | 优点 | 缺点 |
|--------|---------|------|------|
| **Recursive（递归）** | 通用场景 | 智能分割，保持语义 | 配置较复杂 |
| **ByParagraph（段落）** | 结构化文档 | 保持段落完整 | 段落过长时效果差 |
| **BySentence（句子）** | 短文本 | 粒度细 | 可能切断语义 |
| **ByLine（行）** | 日志、代码 | 简单直接 | 不适合长段落 |
| **ByWord（单词）** | 英文文本 | 精确控制长度 | 中文不适用 |
| **ByCharacter（字符）** | 固定长度需求 | 最简单 | 可能切断单词 |
| **ByRegex（正则）** | 自定义规则 | 灵活 | 需熟悉正则 |

**推荐使用 Recursive 分割器**：

```java
import dev.langchain4j.data.document.splitter.DocumentSplitters;

DocumentSplitter splitter = DocumentSplitters.recursive(
    300,  // 每块约 300 字符
    30    // 重叠区 30 字符，防止知识断裂
);

List<TextSegment> segments = splitter.split(document);
```

**工作原理**：
```
1. 先尝试按段落分割
2. 如果段落太长，按句子分割
3. 如果句子还长，按单词分割
4. 最后按字符分割

✅ 智能降级，保持最大语义单元
```

**配置说明**：

1. **API Key**
   - 从 Pinecone 控制台获取
   - 建议存储在环境变量或配置文件中

2. **Index（索引）**
   - 如果不存在，会自动创建
   - 一个项目可以有多个索引

3. **Namespace（命名空间）**
   - 逻辑隔离不同数据集
   - 例如：`prod`、`test`、`dev`

4. **Dimension（维度）**
   - 必须与嵌入模型的维度一致
   - `text-embedding-v4` 输出 1024 维

### 4.2 其他向量数据库对比

| 数据库 | 类型 | 部署难度 | 性能 | 成本 | 适用场景 |
|--------|------|---------|------|------|---------|
| **Pinecone** | 云端托管 | 低 | 高 | 中 | 快速上线 |
| **Chroma** | 本地/云端 | 低 | 中 | 低 | 中小规模 |
| **Qdrant** | 本地/云端 | 中 | 高 | 中 | 高性能需求 |
| **Milvus** | 分布式 | 高 | 极高 | 高 | 亿级数据 |
| **InMemory** | 内存 | 极低 | 中 | 无 | 开发测试 |

**选型建议**：
- 开发阶段 → InMemory（零配置）
- 小规模生产 → Chroma/Qdrant
- 大规模生产 → Milvus/Pinecone

### 4.3 文档摄入流水线

```java
import dev.langchain4j.data.document.Document;
import dev.langchain4j.data.document.DocumentSplitter;
import dev.langchain4j.data.segment.TextSegment;
import dev.langchain4j.model.embedding.EmbeddingModel;
import dev.langchain4j.store.embedding.EmbeddingStore;
import dev.langchain4j.store.embedding.EmbeddingStoreIngestor;

// 1. 加载文档
Document document = FileSystemDocumentLoader.loadDocument(docPath);

// 2. 分割文档
DocumentSplitter splitter = new MyDocumentSplitter();
List<TextSegment> segments = splitter.split(document);

// 3. 向量化并存储
EmbeddingStoreIngestor ingestor = EmbeddingStoreIngestor.builder()
    .documentSplitter(splitter)
    .embeddingModel(embeddingModel)
    .embeddingStore(embeddingStore)
    .build();

ingestor.ingest(document);

System.out.println("文档摄入完成，共 " + segments.size() + " 个片段");
```

**工作流程**：
```
文档 → 分割器 → 文本片段 → 嵌入模型 → 向量 → 向量数据库
                                    ↓
                              片段 + 向量一起存储
```

```java
    contentRetriever = "contentRetriever"    // 内容检索器（RAG）
)
public interface MTAIService {

    @SystemMessage("你是美团外卖客服机器人，专门回答美团外卖相关问题")
    @UserMessage("我是用户：{{message}}")
    String sendMessage(@MemoryId String sessionId, @V("message") String message);
}
```

**注解说明**：

1. **`@AiService`**
   - 标记为 AI Service 接口
   - `wiringMode = EXPLICIT`：显式指定依赖

2. **`@SystemMessage`**
   - 系统级指令
   - 定义 AI 的角色和行为

3. **`@UserMessage`**
   - 用户消息模板
   - `{{message}}` 是占位符

4. **`@MemoryId`**
   - 会话 ID，用于隔离不同用户的对话历史

5. **`@V("message")`**
   - 变量绑定，将参数映射到模板

### 5.2 ContentRetriever 配置

```java
package com.langchain4j;

import dev.langchain4j.model.embedding.EmbeddingModel;
import dev.langchain4j.rag.content.retriever.ContentRetriever;
import dev.langchain4j.rag.content.retriever.EmbeddingStoreContentRetriever;
import dev.langchain4j.store.embedding.EmbeddingStore;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class AgentConfig {

    @Autowired
    private EmbeddingModel embeddingModel;
    
    @Autowired
    private EmbeddingStore embeddingStore;

    @Bean
    ContentRetriever contentRetriever(){
        return EmbeddingStoreContentRetriever.builder()
            .embeddingStore(embeddingStore)
            .embeddingModel(embeddingModel)
            .maxResults(1)      // 最多返回 1 条结果
            .minScore(0.8)      // 最低相似度阈值
            .build();
    }
}
```

**参数调优**：

| 参数 | 默认值 | 建议值 | 说明 |
|------|--------|--------|------|
| **maxResults** | 3 | 1-5 | 召回片段数量 |
| **minScore** | 0.0 | 0.7-0.9 | 相似度阈值 |
| **maxSegmentsPerEmbedding** | 1 | 1 | 每个向量的片段数 |

**调优策略**：
- 提高 `minScore` → 减少噪声，但可能漏检
- 降低 `minScore` → 提高召回率，但引入噪声

```java
     */
```

## 六、增量更新与性能优化

### 6.1 增量更新策略

**问题**：每天新增 10 份文档，如何避免重新向量化所有文档？

**解决方案**：记录已处理的文档，只处理新增文档。

```java
import java.nio.file.Files;
import java.nio.file.Path;
import java.nio.file.attribute.BasicFileAttributes;
import java.util.Set;
import java.util.HashSet;

public class IncrementalIndexer {

    private Set<String> processedFiles = new HashSet<>();

    /**
     * 增量索引文档
     */
    public void incrementalIndex(Path docsDir, EmbeddingStore<TextSegment> store, 
                                  EmbeddingModel embeddingModel) throws Exception {
        
        // 遍历目录下所有文件
        Files.list(docsDir).forEach(filePath -> {
            try {
                // 获取文件最后修改时间
                BasicFileAttributes attrs = Files.readAttributes(filePath, BasicFileAttributes.class);
                String fileKey = filePath.toString() + ":" + attrs.lastModifiedTime().toMillis();
                
                // 如果文件未处理过，或已修改
                if (!processedFiles.contains(fileKey)) {
                    System.out.println("处理新文档: " + filePath.getFileName());
                    
                    // 加载并摄入文档
                    Document document = FileSystemDocumentLoader.loadDocument(filePath);
                    EmbeddingStoreIngestor ingestor = EmbeddingStoreIngestor.builder()
                        .embeddingModel(embeddingModel)
                        .embeddingStore(store)
                        .build();
                    ingestor.ingest(document);
                    
                    // 标记为已处理
                    processedFiles.add(fileKey);
                }
            } catch (Exception e) {
                e.printStackTrace();
            }
        });
    }
}
```

**工作流程**：
```
第一次运行：
- 处理 1000 份文档 → 耗时 2 小时
- 记录文件指纹到 processedFiles

第二天（新增 10 份）：
- 扫描目录，发现 10 份新文档
- 只处理这 10 份 → 耗时 5 分钟 ✅
- 更新 processedFiles
```

### 6.2 缓存热点问答

**问题**：高频问题重复调用 LLM，浪费 Token 和延迟。

**解决方案**：缓存常见问题的答案。

```java
import java.util.Map;
import java.util.concurrent.ConcurrentHashMap;

public class CachedAssistant {

    private Map<String, String> answerCache = new ConcurrentHashMap<>();
    private MTAIService aiService;

    public String ask(String sessionId, String question) {
        // 1. 检查缓存
        String cachedAnswer = answerCache.get(question);
        if (cachedAnswer != null) {
            System.out.println("命中缓存");
            return cachedAnswer;
        }

        // 2. 调用 AI Service
        String answer = aiService.sendMessage(sessionId, question);

        // 3. 写入缓存
        answerCache.put(question, answer);

        return answer;
    }
}
```

**性能提升**：
- 缓存命中率：60%~80%（常见问题）
- 平均延迟：从 2 秒降至 0.1 秒
- Token 成本：节省 50%~70%
